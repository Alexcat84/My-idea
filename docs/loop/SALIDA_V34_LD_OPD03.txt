NODO: ab_testing_optimizacion
  titulo    : A/B Testing para Optimización Web/Mobile
  fuente    : The Startup Owner's Manual - Steve Blank
  dominio   : core   fase: validacion   vivo: True
  entregable: Plan de pruebas A/B con elementos priorizados, resultados documentados y decisión sobre la versión ganadora
  resumen   : El A/B testing es el método más usado para optimizar actividades de 'get, keep and grow' en negocios web y móviles. Consiste en comparar dos versiones de una página web (o elemento) para determinar cuál produce mejores resultados, mostrando la versión 'A' a la mitad de los visitantes y la versión 'B' a la otra mitad, de forma alternada y secuencial.
  PASOS (5):
     1. Identificar los elementos clave de la landing page que impulsan la activación (botones, titulares, imágenes, ofertas), eligiendo antes la métrica clave a mejorar (ej. tasa de registro) y contando también la ubicación de CTA, el copy, la prueba social y el número de campos de formulario.
     2. Diseñar dos versiones (A y B) cambiando un solo elemento a la vez, generando las hipótesis de cambios grandes antes que las de pequeños ajustes.
     3. Dividir el tráfico de manera aleatoria y equitativa entre ambas versiones (o 80/20 en páginas de alto tráfico), y dejar correr la prueba durante semanas enfocándose en una sola métrica a la vez.
     4. Medir resultados de conversión/activación para cada versión
     5. Implementar la versión ganadora y repetir el proceso con nuevos elementos, documentando los resultados y pasando a la siguiente métrica cuando se agoten las ideas.
  CONDICIONES (2):
     1. Cuando el startup ya tiene tráfico web/mobile pero necesita mejorar tasas de conversión
     2. Cuando se busca optimizar continuamente cualquier paso del funnel de adquisición

NODO: split_testing_experimentos_ab
  titulo    : Split-Testing (Pruebas A/B)
  fuente    : The Lean Startup - Eric Ries
  dominio   : core   fase: validacion   vivo: True
  entregable: Reporte de resultados de al menos un experimento A/B con conclusiones sobre el impacto de una funcionalidad en el comportamiento del cliente
  resumen   : Técnica en la que se ofrecen diferentes versiones de un producto a distintos grupos de clientes simultáneamente, para observar diferencias en el comportamiento y así inferir el impacto real de cada variación. A diferencia del análisis de causa-efecto posterior (que es lento y ambiguo), el split-test genera evidencia científica en tiempo real sobre qué cambios importan realmente a los clientes.
  PASOS (5):
     1. Definir una hipótesis clara sobre el impacto esperado de una nueva funcionalidad
     2. Dividir la base de clientes en dos grupos aleatorios (A y B)
     3. Lanzar la variación nueva solo al grupo B, manteniendo el grupo A con la versión estándar
     4. Medir comportamiento de ambos grupos usando las mismas métricas
     5. Comparar resultados para determinar si la variación tuvo impacto real
  CONDICIONES (2):
     1. Si el equipo no puede determinar con certeza qué causó un cambio en las métricas
     2. Si se quiere decidir entre priorizar nuevas funcionalidades sin desperdiciar recursos de desarrollo
