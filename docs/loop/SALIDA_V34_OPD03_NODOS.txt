  fuente     : The Startup Owner's Manual - Steve Blank
  deprecado  : False
  alias      : []
  etiqueta   : Compara Versiones, Mejora Resultados
  PASOS (10):
     1. Identificar los elementos clave de la landing page que impulsan la activación (botones, titulares, imágenes, ofertas)
     2. Diseñar dos versiones (A y B) cambiando un solo elemento a la vez
     3. Dividir el tráfico de manera aleatoria y equitativa entre ambas versiones (o 80/20 en páginas de alto tráfico)
     4. Medir resultados de conversión/activación para cada versión
     5. Implementar la versión ganadora y repetir el proceso con nuevos elementos
     6. Elegir una métrica clave a mejorar (ej. tasa de registro)
     7. Generar hipótesis de cambios grandes antes que pequeños ajustes
     8. Ejecutar pruebas A/B durante semanas enfocándose en una sola métrica a la vez
     9. Probar elementos como botones, ubicación de CTA, copy, prueba social, número de campos de formulario
    10. Documentar resultados y pasar a la siguiente métrica cuando se agoten las ideas
  CONDICIONES (2):
     1. Cuando el startup ya tiene tráfico web/mobile pero necesita mejorar tasas de conversión
     2. Cuando se busca optimizar continuamente cualquier paso del funnel de adquisición
  ENTREGABLE : Plan de pruebas A/B con elementos priorizados, resultados documentados y decisión sobre la versión ganadora

==============================================================================
  dominio    : core
  titulo     : Split-Testing (Pruebas A/B)
  fuente     : The Lean Startup - Eric Ries
  deprecado  : False
  alias      : []
  etiqueta   : Prueba Versiones, Mide Resultados
  PASOS (5):
     1. Definir una hipótesis clara sobre el impacto esperado de una nueva funcionalidad
     2. Dividir la base de clientes en dos grupos aleatorios (A y B)
     3. Lanzar la variación nueva solo al grupo B, manteniendo el grupo A con la versión estándar
     4. Medir comportamiento de ambos grupos usando las mismas métricas
     5. Comparar resultados para determinar si la variación tuvo impacto real
  CONDICIONES (2):
     1. Si el equipo no puede determinar con certeza qué causó un cambio en las métricas
     2. Si se quiere decidir entre priorizar nuevas funcionalidades sin desperdiciar recursos de desarrollo
  ENTREGABLE : Reporte de resultados de al menos un experimento A/B con conclusiones sobre el impacto de una funcionalidad en el comportamiento del cliente
